# Third-party assets: what is deliberately not bundled

**Nothing in this repository belongs to anyone else.** Every file is either
source code written for this project or synthetic content generated by
`tools/`.

That is a deliberate position, not an accident of scope. A thesis pipeline is
tempted to ship three kinds of asset, and all three are problems.

## University format specifications

Nearly every institution publishes a document describing its thesis format:
margins, heading fonts, the wording of the cover, the order of the front matter.
Users of a formatting tool naturally want those encoded and shipped.

They are not. Two reasons:

- **Copyright.** The specification is the institution's document. Bundling it,
  or a derivative of it, is a licence question this project does not want to
  answer per institution.
- **Staleness.** A bundled specification is wrong the moment the institution
  revises it, and a user following a stale specification submits a
  non-conforming thesis with confidence.

The structure that *is* shipped is `thesis_refinery/style.py`: a set of named
formatting facts with neutral defaults. Transcribe your own institution's
requirements into `thesis.yml`. That transcription is also the moment you find
out which of its requirements are ambiguous, which is worth knowing before you
submit rather than after.

## The reference `.docx` a renderer needs

Quarto and pandoc both accept a `reference.docx` that defines the styles the
output uses. The natural move is to point at a document that already looks right
— which is usually somebody's thesis, or the institution's own sample.

The bundled example uses one generated from scratch by
`tools/make_reference_docx.py`. It defines only the styles the pipeline needs, in
neutral fonts, and it is regenerable, reviewable and unencumbered.

## Published figures and instrument output

A real thesis contains figures reproduced from journals and spectra exported from
instruments. Both are copyrighted or personal, and neither belongs in a public
repository — not in `examples/`, not in `tests/`, not as "a small sample".

The example thesis therefore uses an image generated by
`tools/make_placeholder_image.py`: a grey rectangle, written pixel by pixel with
no image library. It is obviously not real data, which is the point — anyone can
tell at a glance that the demo is a demo.

## Citation styles (CSL)

Citation Style Language styles are widely available and are usually licensed
**CC-BY-SA**, which is not compatible with combining them into an AGPL-3.0 work.

None is bundled. If you want CSL-driven references, install the style from the
[Zotero style repository](https://www.zotero.org/styles) yourself. Note that the
pipeline does not need CSL at all: references are hand-numbered markdown, which
is the source of truth, and the reference stage normalises the *records* rather
than re-numbering them.

## Runtime dependencies

`python-docx`, `lxml`, `PyYAML` and (for the chemistry profile) `openpyxl` are
runtime dependencies under their own licences, listed in `pyproject.toml`.

Quarto and pandoc are invoked as **separate processes**, never linked. Running a
GPL- or MIT-licensed program alongside this one does not make this one a
derivative of it, and this project does not vendor either.

## If you want to contribute an institution's format

Contribute the *structure*, not the document:

- a `StyleSpec` populated with the values, as a documented example, and
- a note in the pull request about where each value came from.

Do not paste the specification's text, and do not attach the institution's
sample thesis or its `reference.docx`. If the format is not expressible in
`StyleSpec`, that is a useful bug report about the specification's expressiveness
— file it as one.
