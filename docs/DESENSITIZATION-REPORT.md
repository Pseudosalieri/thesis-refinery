# Desensitisation report

What was removed, what was rewritten, and how the removal is verified.

This repository is a generalisation of a private thesis pipeline. The private
material was never copied here and then deleted — deletion leaves history, and
history is what gets published. Instead every module that came across was
**rewritten**: read, understood, and re-expressed with the thesis-specific parts
replaced by configuration.

## The rule

Nothing that identifies the original thesis, its author, its institution, or the
machine it was written on may appear in a file git would publish.

`tools/check_desensitized.py` enforces that mechanically. It scans
`git ls-files --cached --others --exclude-standard` — exactly the set of files a
clone would receive — applies a deny-list of regular expressions grouped by what
leaks, and exits non-zero on any hit. It runs first in CI, before the test
matrix, so a leak cannot be masked by an unrelated failure.

The deny-list is in one place and is reviewed like any other code. Adding an
entry is a pull request; weakening one to make a change pass is not.

## Categories removed

Recorded by category rather than by example, because *this file is published* and
listing the strings would reintroduce exactly what the gate exists to catch. The
literal list lives in `.baseline/desensitization-detail.md`, which is gitignored
and never leaves the machine that produced it.

| Category | What it covers | Disposition |
|---|---|---|
| People | The author, the supervisor, and authors of related work cited as samples | Excluded entirely. The only identity strings this project ships are empty defaults. |
| Institutions | The degree-granting institution, its faculty, and its degree programme | Excluded. Formatting facts are examples; which institution they came from is not recorded. |
| The thesis itself | Title, subject area, target, and the compound or sample naming scheme | Excluded, and the naming scheme is now a configuration value. |
| Private machine paths | Absolute paths into the author's working directories and tool installations | Replaced by paths relative to the project root, plus PATH lookup. One hard-coded tool path in the original had already gone stale on the author's own machine. |
| Data assets | Spectra, structure images, instrument exports, docking output, and a bibliography of real references | Not copied. The example thesis is generated by `tools/`. |
| Third-party documents | The institution's format specification, its sample thesis, and published figures | Not copied. See [`third-party.md`](third-party.md). |
| Private ledgers | An inventory that mapped private paths, file hashes and previous students' documents | Not copied. `ledger/` was written fresh against a repository-relative model. |

## Detail: what "rewritten" meant in practice

Three patterns came up repeatedly, and each is worth naming because the same
three will come up for anyone generalising a personal tool.

**A literal becomes a field.** A thesis title hard-coded to detect and delete a
renderer's generated title page became a boolean in the configuration. A running
head became `HeaderFooterSpec.odd_page_text`, with a note that its default is a
default and not a fact.

**A naming scheme becomes a manifest.** The original hard-wired one chemistry
naming convention into a spectra-appendix stage: column names, filename
templates, caption wording. That is now a manifest the user describes, and the
code contains no naming scheme at all.

**A data table becomes an empty default.** A stage carried a table of specific
bibliographic records to rewrite. The mechanism stayed; the table became
configuration, and the shipped default is empty.

## Verification

Three independent checks, all of which run in CI:

1. **The gate**, on every push, first and alone.
2. **A negative test** (`tests/test_desensitized_gate.py`) that plants a
   prohibited token in a throwaway git repository and asserts the gate fails,
   plus one that asserts it passes on a clean tree. A gate that has never been
   observed failing is not a gate.
3. **A review pass** over this report against the local detail file, before the
   first push. Recorded in [`PUBLISH-CHECKLIST.md`](PUBLISH-CHECKLIST.md).

The gate found real leaks twice, both in this repository's own documentation,
both written by someone who knew the rule. That is the argument for running it
rather than trusting care.

## What the gate does not catch

Stated plainly, because a green gate is easy to over-read:

- **Anything in an image.** A photograph of a cover page is not text. The
  policy is that no such image is ever added; the gate cannot enforce it.
- **Anything inferable.** A distinctive combination of formatting facts may
  identify an institution to someone who knows it. This project ships neutral
  examples for that reason.
- **Anything in git history.** The gate scans the working tree. This repository
  was created from scratch precisely so its history contains no private
  material; a future contributor importing files from elsewhere must preserve
  that property themselves.
- **Anything already in the deny-list's blind spot.** The list encodes what was
  known to be sensitive. Add to it.
