# demo-thesis — the bundled example

A complete, buildable thesis project: the thing `thesis-refinery build` is
demonstrated on, and a worked example of the layout a real project uses.

`thesis-refinery init` does **not** copy this. It scaffolds an empty project with
the same shape and none of the prose, because inheriting a demo's synthetic
content — its fake references, its placeholder tables — means the first task of a
new project is cleaning it out, and that is the kind of task that gets half done.

**Every word of it is synthetic.** The measurement procedure it studies does not
exist; the specimens, the units and every number were chosen in advance to be
obviously arbitrary; the references point at `10.0000/example.*` DOIs under names
such as `Example A`, in journals such as `Journal of Synthetic Examples`; and the
one figure is a grey rectangle drawn by a script in this repository. Nothing here
identifies a real person, institution, instrument or material.

That is a requirement rather than a nicety. A demo that looks like real work invites
somebody to cite it, and a demo borrowed from a real project drags that project's
identity into a public repository — see [`CONTRIBUTING.md`](../../CONTRIBUTING.md)
and [`docs/third-party.md`](../../docs/third-party.md).

## What is here

| Path | What it is |
|---|---|
| `thesis.yml` | The project configuration: paths, style values, identity strings, expected counts. |
| `manuscript/_quarto.yml` | The Quarto project. Renders `index.qmd` to `docx`. |
| `manuscript/index.qmd` | The document title and the chapter include list. |
| `manuscript/chapters/` | The nine chapter sources, and `chapters/raw/media/` for their images. |
| `manuscript/reference.docx` | The style template the renderer reads. Generated by `tools/make_reference_docx.py`, never copied from anyone's document. |

`manuscript/_outputs/` and `.quarto/` are build products and are not tracked.

## Build it

```bash
thesis-refinery build examples/demo-thesis     # render, apply the style, run the gates
thesis-refinery verify --project-dir examples/demo-thesis
thesis-refinery audit  --project-dir examples/demo-thesis
```

Quarto has to be on `PATH` for the render step; everything after it works on the
`.docx` alone.

The generated assets are reproducible rather than precious. If they are missing, or
you have edited the styles, rebuild them:

```bash
python tools/make_reference_docx.py      # manuscript/reference.docx
python tools/make_placeholder_image.py   # chapters/raw/media/placeholder.png
```

Both take no arguments and are idempotent: running either one twice leaves a
byte-identical file behind.

## Starting your own project

Copy the shape, not the prose:

1. **`thesis.yml`** — keep the structure. The three sections that need real values
   are `identity` (the strings your cover must contain), `style.header_footer`
   (your institution's running head) and `checks` (leave them at `auto` until you
   have a reason to pin a number).
2. **`manuscript/_quarto.yml` and `index.qmd`** — keep the include list; replace the
   title and add your chapters to `chapters/`. Every chapter named in `index.qmd`
   must exist, or the render fails with a missing-file error rather than silently
   dropping it.
3. **`manuscript/chapters/*.qmd`** — replace the files. Keep the level convention
   (`#` for a chapter title, `##` and `###` below it), put table captions above the
   table and figure captions under the figure, and start each caption with a prefix
   from `style.caption.image_prefixes` / `table_prefixes`.
4. **The two generators in `tools/`** — the parts you are meant to delete. Once you
   have your own institution's `reference.docx` and your own figures, you do not
   need either, and `thesis.yml`'s `reference_docx` should point at your template.
